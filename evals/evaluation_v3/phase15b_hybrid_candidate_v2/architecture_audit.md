# EvidenceFlow Phase 15B Hybrid Candidate Retrieval Benchmark v2

## Scope and immutability

- This is a new artifact version. All files under `phase15b_hybrid_candidate_v1/` remain frozen and are not overwritten.
- The benchmark is offline and read-only with respect to Production Runtime, the active Chroma Collection, Gold, canonical qrels, and mapping.
- Phase 15C is not entered by this run.

## Formal B0 contract

The formal final baseline is the current Production retrieval path:

```text
Dense Top20 → BAAI/bge-reranker-base → Top5
```

The numeric Phase13F values are retained only under the classification:

```text
RAW_DENSE20_TOP5 / PRE_RERANK_REFERENCE
```

They are not a post-reranker Gate.

## Independent replay Gate

`production_reranked_baseline.json` is generated by
`experiments/run_production_reranked_baseline_replay.py`, which does not import the
Phase15B benchmark runner. It uses the frozen 40-question set, the active v2
Collection, the Production Dense→Reranker wrapper, and the same read-only active
relevance projection. The projection is identified by
`active_relevance_projection_hash`.

The benchmark runner first executes B0 and compares its per-question Top5 IDs,
@5 summary, pipeline identity, Collection identity, and projection Hash to the
independent replay. Any mismatch writes a STOP result and exits before Dense40,
BM25-20, or the Dense20∪BM25-20 arm is executed.

## Candidate arms

Only after B0 replay parity passes:

| Arm | Candidate contract | Reranker input |
|---|---|---|
| B0 | Production Dense20 | Dense20 |
| B1 | Dense40 | Dense40 |
| B2 | BM25-20 | BM25-20 |
| B3 | Dense20 then BM25-only set union, max 40 | union IDs only |

No RRF, score fusion, or Runtime promotion is performed.

## Decision rule

Dense40 is considered clearly superior only when both `Recall@5` and `nDCG@5`
exceed both formal B0 and B3 by an absolute margin of at least `0.005`.
If all gates pass and that condition holds, Phase15B is `PASS` but the Hybrid
recommendation is `DO_NOT_PROMOTE`; any candidate-depth follow-up is a separate
future experiment and does not modify Runtime.
